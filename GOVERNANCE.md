# Governance

## Model

Projects under the `NikaSir` account use a maintainer-led governance model.

## Decision making

- Routine fixes and documentation changes are reviewed on technical merit.
- Changes affecting architecture, compatibility, public interfaces, data models, device-control behavior, security, or release policy require explicit maintainer approval.
- The repository owner has final responsibility for accepting or rejecting changes and for release decisions.

## Traceability

Significant changes should be traceable through issues, pull requests, source
commits, changelog entries and versioned validation evidence. NikaS publication
uses reviewed `main` changes; GitHub Releases and automatic release tags are not
created. Historical tags are not changed by tooling adoption.

## Repository autonomy

Individual repositories may define stricter governance, release gates, test requirements, or compatibility rules. Repository-specific rules take precedence over these defaults.
